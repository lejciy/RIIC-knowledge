# skill-1 检索路由与歧义消解

> 使用时机：所有需要检索知识库的问题，在第一次检索之前执行。玩家提问大量使用俗称、简称与合称，按字面检索会漏检或错检；知识库已内置消歧真源，本 skill 把「先消歧、再路由」固化为必走步骤。

## 执行流程

### 第一步：抽取实体

从问题中抽出待检实体：干员名（含昵称，如「肥鸭」=菲亚梅塔）、「XX组」「XX体系」类组合名、技能名、设施名、布局代号（243/252/333/342/153）、产物名（赤金/合成玉/源石碎片/经验书）。产物俗称先归一：狗粮/经验书/书＝作战记录，金条/金＝赤金，钱＝龙门币，玉＝合成玉，土＝固源岩。

### 第二步：组合名消歧

组合名先查三处，确认提问指向哪个组合：

1. `docs/3-组合库/歧义/歧义-组合别名.md` —— 社区俗称与正式组合的对应（如「巫恋组」是「龙舌兰组」的别名）。
2. `docs/3-组合库/歧义/歧义-简称合称.md`、`docs/3-组合库/歧义/歧义-子串对.md` —— 一个名字同时命中多个组合、或名字是另一组合子串的情况。
3. `docs/3-组合库/组合注册表.md`·全库词表 —— 核对规范名称和组合身份；具体启用条件、分支及降级用法回到对应深稿核对。

### 第三步：技能名消歧

提到技能名时，先查 `docs/2-干员技能/技能等价组.md`（同效不同名）：同一组内官方显示名不同但效果逐字相同，**整组持有者都是候选**。典型：「裁缝 β」组实际包含 `手工艺品·β`（卡夫卡）、`鉴定师的手段`（折光）等同效持有者；只按字面技能名检索会漏掉大部分候选人。

### 第四步：干员名定位

干员名查 `docs/2-干员技能/名册.md` 确认设施归属与技能快照位置；不确定某干员是否被知识库收录时，也以名册为准。

### 第五步：按问题类型路由到模块

| 问题在问什么 | 去哪个模块 |
|---|---|
| 机制怎么运转、面板规则、资源常数 | `docs/1-基础设定/`（结算规则→设施与进驻→资源体系） |
| 某干员/某技能的效果原文与原理 | `docs/2-干员技能/`（快照 + `释义/`） |
| 组合成员、档位、互斥、替代 | `docs/3-组合库/`（注册表→总览→深稿→高效率散件） |
| 排班方案为什么长这样、结果怎么读 | `docs/4-排班算法/` |
| 游戏内怎么换班、班型怎么排 | `docs/5-换班操作/`（定时/错班/队列/动态/自动五篇） |
| 值不值得、怎么选、优先级 | `docs/6-专家经验/` |
| 布局选择、无人机投向、钱书价值 | `docs/7-基建布局/` |

### 第六步：扩展检索词后检索

用消歧得到的正式名 + 原始俗称检索。注册表负责名称和身份，总览负责导航与互斥，深稿负责条件、分支、降级和用法，释义负责隐性机制；按问题对应的信息分工取证，不设置全局覆盖顺序。网站技能问题固定先 query_skills，再 kb_route 定位释义并 kb_read 阅读相关正文；有用法或组合问题时继续读取对应深稿。

## 红线

- 俗称未消歧前，不得按字面命中就直接下结论；命中空结果时先换正式名重试，仍空才判断「库内没有」。
- 消歧后仍有多个候选组合且无法从问题上下文判断时，向用户列出候选并询问，不得默认取其中一个。

## 输出要求

消歧结果对用户透明：回答中首次提到组合/技能时，必要时用「XX（即 YY）」说明对应关系，后续用正式名。
