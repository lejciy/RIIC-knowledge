# skill-7 练卡取舍与回本判断

> 使用时机：「XX 值得为基建练吗」「先练谁」「XX 精二多久回本」「克里斯汀要不要练」。答案 = 取向规则（`docs/6-专家经验/练卡取向.md`）＋该干员的组合身份与散件档位（注册表/散件表）＋成本（升级消耗表）＋差值收益（产出基准），跨四个模块取数，单次检索必断链。本 skill 固化「定身份 → 套判据 → 算回本 → 按玩家类型给顺序」的步骤。

## 执行流程

### 第一步：按 skill-1 消歧后确定干员的基建身份

查 `docs/3-组合库/组合注册表.md`（是否组合成员、层级、目标练度）与 `docs/3-组合库/高效率散件.md`（散件档位、效率与成立条件）。同一干员两者都有时，组合身份优先于散件身份（散件表·使用口径）——问「酒神值不值得练」先答红云组分支，再答 35% 散件档。

### 第二步：对照五档判据给出结论

对照 `docs/6-专家经验/练卡取向.md`·推荐名录：必练必拿（机制核心）→ 超级推荐（组合与体系核心）→ 练了可以一直用（40% 档散件、单精二带组合）→ 酌情考虑（高成本组合）→ 不推荐（无组合身份、精二仅达 35% 参考线的纯数值散件）。目标练度一律引用注册表/散件表原文，不在此重复。

### 第三步：回本类问题走双材料口径

成本侧查 `docs/1-基础设定/资源体系/干员升级与模组消耗.md`（关键节点全局累计），收益侧按 skill-2 第一至四步取数。练卡取舍按**提升差值口径**（新干员 − 原站位干员）算（练卡取向·回本口径），口径声明沿用 skill-2 第六步：两种口径周期差数倍，回答时写明采用哪一种或并列呈现；资源背景（月进项量级）引用练卡取向·资源背景，不另行估算。

### 第四步：按玩家类型定先后

用户自述平铺精二／常规／搓玉时，培养顺序按练卡取向·游戏目标分型；搓玉玩家先查 `docs/6-专家经验/搓玉.md`·基建工具人的投资边界——搓玉收益不受工具人投资影响，该节列为可暂缓的组合不得推为优先。

### 第五步：新手下限与梯度上限分开

用户是新手或 box 浅时，先给 `docs/6-专家经验/新手培养.md` 的最低目标（够用即可），再按练卡取向给后续方向；两者对同一干员的目标不同时（如苍苔精零起步、精二上限），按新手培养·重复推荐与目标区分处理，属两个待办。

## 红线

- 不评价名册查无的干员；库内没有的组合身份不编造。
- 成员、练度、效率数值一律引用真源文件；本 skill 与练卡取向稿都不复制数值表（月进项等经验口径数字随取向稿维护）。
- 「值不值得」的结论必须落到判据（效率增量、保值性、玩家类型）上，不得只凭干员知名度作答；纯数值散件的不推荐结论须附差值账（约 5% → 日产值增量约 400 经验／500 贸易收入）。

## 输出要求

结论（练／缓练／不练＋目标练度）→ 判据（组合身份或散件档位、五档中的哪一档）→ 回本问题时给差值口径算式与周期量级 → 玩家类型适配（用户已自述类型时必给）。
