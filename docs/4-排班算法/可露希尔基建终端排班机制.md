# 可露希尔基建终端排班机制

> 本文说明可露希尔基建终端（riic.autos）如何从输入生成一份完整排班结果：输入项、落位顺序、三种轮换方式的生成骨架、输出形态与结果解释口径。班制的时间配置数学与游戏内执行见 [[定时换班]]与 [[错班轮换]]；心情与工休比公式见 [[心情与宿舍]]。

## 输入

生成排班需要四类输入：

- **干员盒**：干员拥有情况、练度、精英化阶段、技能解锁状态与潜能。
- **基建布局**：各房间的类型、等级与容量，贸易站的订单，制造站的配方，宿舍的床位数。
- **轮换方式**：一天三换 12/6/6、三等分三班 12/12/12、主备轮换 12/12 三选一。
- **菲亚梅塔开关与功能位策略**：是否启用菲亚梅塔，以及功能位策略。

## 落位顺序

排班按固定次序逐段落位，前一段的结果决定后一段可选的人选：

1. **固定体系计划先落位**：符合体系规则的控制、贸易、制造等硬性安排最先写入；硬性安排不合法会直接失败，不会静默跳过。
2. **动态中枢比较**：对可选的动态中枢班底逐套试排——先补贸易/制造，再补发电，然后比较贸易和制造两边的最终表现，选出一套。
3. **贸易/制造优先，发电随后**：生产核心先占人，发电主要使用剩余人员，避免抢走贸易和制造的关键成员。
4. **办公室先于会客室**：办公室逐人择优，会客室按组合效果选人；两者之后再做支持合同、挂件和低消耗房落位。
5. **跨设施效果按实际在岗结算**：中枢、[[自动化组]]、[[红松林骑士组]]、[[感知信息组]]、[[人间烟火组]]等效果，只有对应来源和受益设施实际在岗时才生效。
6. **补中枢普通位和注入位，再做检查**：生产房定型后补一次中枢普通位/全局注入；最后检查占用、容量、配方、心情和轮换关系。

## 三种轮换方式

### 12/6/6 与 12/12/12：同一套三班半区骨架

两种方式共用同一套三班半区轮换骨架：第一班两个半区都在岗；第二班一个半区继续，另一个半区换替补；第三班反过来。输出用 α、β、γ 标识各班的在岗和休息班底。两者的区别只在每班时长（12/6/6 为 12h＋6h＋6h，12/12/12 为三个等长 12h 班）。这一骨架与手动错班轮换的三组三班结构对应（见 [[错班轮换]]·三组三班的标准结构）。

### 12/12：主力/替补互斥

第一班为主力；第二班把第一班所有消耗心情的工作区人员排除后重新排一套，中枢也重新安排。主力班与替补班由此互斥。

### 三班全勤与跨班继承

- 三班全勤只做质量警告，不使排班失败；菲亚梅塔真实交换目标除外（换心情机制见 [[菲亚梅塔]]）。
- 跨班只继承规则要求的内容，例如心情、连续工作时长和同进退（同上同下）关系；当班临时加成不直接复制到下一班。

## 输出

| 入口 | 输出内容 |
|---|---|
| 命令行 `plan` | 各班房间和干员、班次汇总、日产出 |
| 命令行 `plan --json` | 各班房间、菲亚梅塔动作、日汇总 |
| 服务端 `plan.compute` | 逐班房间表、逐房效率、加权日产出、MAA、练卡建议和 profile |

其中 MAA 指生成的 MAA 自定义基建排班数据，定时时刻表与班次轮滚两种用法见 [[定时换班]]·MAA 执行。

## 结果的解释口径

一份排班结果呈现出的样貌，可以回溯到以下规则：

- **固定体系优先于普通选人**：体系成员由固定体系计划写入，先于普通效率选人落位。
- **中枢看带动后的最终表现**：中枢班底的取舍以试排后贸易、制造两边的最终表现为准，中枢自身数值高低不直接决定结果。
- **贸易/制造优先，发电用剩余人员**：发电站人选来自生产核心占人后的剩余池，不与生产核心争夺关键成员。
- **办公室逐人择优，会客室按组合**：两类房间采用不同的选人逻辑。
- **心情和当班可支撑时长是硬门槛**：两项按硬约束处理，不满足的候选不参与落位。
- **跨设施效果只认实际在岗**：来源或受益设施不在岗时，效果不计入结算。
- **暖机干员尽量回原房，但不保证**：带暖机技能的干员优先安排回原房间，该倾向无硬性保证。
- **体系同进退只覆盖已实现部分**：同进退绑定只对已实现的体系生效。
- **不保证全局最优**：制造站仍按逐房政策选人，结果在该政策空间内成立。
