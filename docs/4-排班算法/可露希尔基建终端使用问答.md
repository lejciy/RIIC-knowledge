# 可露希尔基建终端使用问答

> 本文收录可露希尔基建终端（riic.autos）使用与 MAA 联动的常见问答，覆盖排班表导入 MAA、干员盒导入、无人机投向、排班表班次读法、菲亚梅塔换班选项、宿舍设置、请求限流与注册登录。排班生成机制（输入、落位顺序、轮换骨架）见 [[可露希尔基建终端排班机制]]；班制时间配置与 MAA 两种执行用法见 [[定时换班]]。

## 排班表导入 MAA 的步骤

**问：基建排班工具生成的排班表应该怎么导入 MAA？具体操作步骤是什么？**

1. 在排班工具生成排班。
2. 下载或导出 MAA 自定义基建 JSON。
3. 打开 MAA，进入「基建换班」或「自定义基建」。
4. 导入 JSON 文件。
5. 检查基建布局、设施产物、班次时间和干员名单。
6. 确认无误后，再开启 MAA 自动换班任务。

MAA 不同版本的入口名称可能不同。导入后的两种执行用法——定时时刻表与班次轮流——见 [[定时换班]]·MAA 执行。

## 没有基建技能的干员为什么被排进中枢或会客室

**问：排班工具为什么会把 12F、小车、莱茵这类没有基建技能的干员排进控制中枢或会客室？这样排真的不影响收益吗？**

- 排班会把控制中枢的位置填满：没有对应基建技能的干员作为普通补位进驻，一般不影响收益（空位填充的取向见 [[中枢席位取舍]]·空位填充规则）。
- 进入会客室但不持有相关技能的干员，一般是其他组合或角色的挂件，如娜斯提、缪尔赛斯等。
- 补位的前提是持有用技能的干员仍在其位：补位干员一旦替换了有用技能的干员，就可能降低收益。判断要看整套排班的实际产出，不能只看单个位置。

## 干员盒导入：全角色数据与真实干员盒

**问：通过森空岛导入 Box 后，为什么生成的排班里会出现我没有的干员、或干员数量和实际对不上？误选「全角色导入」后怎么改回自己的干员池？没有森空岛入口的玩家怎么导入干员数据？**

出现未持有干员的原因是误选了「全角色导入」：此时导入的是全角色体验数据，不是自己的真实干员盒。改回方法：

1. 回到「配置 Box 与布局」。
2. 进入第 1 步，点击「更换」。
3. 重新同步森空岛数据，或上传 MAA 导出的 `Arknights_OperBox_Export.json`。

没有森空岛入口的玩家（例如日服玩家），可以使用 MAA 导出的干员 JSON 或其他兼容 Box 文件导入。

## 无人机的投向与修改

**问：工具的无人机是如何使用的？**

- 工具自动根据基建布局和产出数值计算无人机投向：153 布局加速经验，其余布局加速赤金和贸易，目标是使赤金供需缺口最小。
- 无人机加速贸易时严格遵循优先级顺序（七级优先级见 [[无人机使用]]·加速贸易站的优先级）。
- 无人机目标可以修改：生成 MAA 配置后跳转至手动排班，即可对无人机目标进行修改。

## 排班表上的班制数字：888、1266

**问：排班表上「一天两换/三换」后面的数字，如 888、1266，代表什么？轮换表里为什么有的班次阵容相同、有的干员换到另一个设施继续上班？**

数字是班制的各班时长连写，表示一天内各班怎么划分：

- **888** 即 8/8/8：三等分三班，一天三换，24h 周期；
- **1266** 即 12/6/6：一天三换，24h 周期，主力 12h 长班＋两段 6h 短班，主力工时占比更高；
- 一天两换的常见班制是 **1212**（12/12/12）：36h 周期，平均 12h 一换。

全部班制与换班节奏的对照见 [[定时换班]]·操作过程的班制表。

班次阵容的相同与轮转来自三班半区骨架（12/6/6 与 12/12/12 共用，结构见 [[错班轮换]]·设施两半轮转）：

- 第一班（长班）两个半区的主力都在岗；
- 第二班一个半区的主力继续在岗——该半区阵容与上一班相同；另一个半区换上替补组；
- 第三班反过来：休息过的半区主力返回原设施，替补组转去接管另一半区——同一批替补由此换到另一个设施继续上班。

所以「有的班次阵容相同」是延续半区的主力没有变动，「有的干员换到另一个设施继续上班」是替补组依次接管两个半区；排班输出中的 α、β、γ 即各班在岗与休息班底的标识（见 [[可露希尔基建终端排班机制]]·12/6/6 与 12/12/12）。

## 菲亚梅塔换班选项的生效条件

**问：勾选了菲亚梅塔换班选项但排班表里没有体现，或者没启用她却自动写入换心情安排，这类换班选项是怎么生效的？**

菲亚梅塔换班生效需要同时满足：

1. 干员盒里有菲亚梅塔；
2. 当前轮换方式支持她；
3. 存在合法的换班目标；
4. 当前设施和班次满足限制条件。

勾选不代表每一班都会使用她。基于当前设计规则，开启菲亚梅塔但未使用，通常是计算认为巫恋、但书、可露希尔三组轮流上的收益更高：强行使用菲亚梅塔会导致但书或可露希尔带低效率的替补队友，总产出反而不如不用菲亚梅塔。此时可以把菲亚梅塔自由分配给制造等其他角色。

关闭后仍然出现菲亚梅塔换心情安排，通常是旧排班结果或旧请求参数残留，修改设置后重新生成排班即可（换心情机制见 [[菲亚梅塔]]；三组轮换贸易站的编排示例见 [[定时换班]]·操作过程）。

## 导入 MAA 后换下干员不进宿舍

**问：排班表导入 MAA 自动换班后，为什么换下来的干员不会被自动安排进宿舍休息？宿舍里应该锁定哪些干员？**

1. 检查 MAA 设置中设施的执行顺序，把宿舍放到最后。
2. 宿舍不要锁定人员——锁定人员会导致换班异常（MAA 换班与宿舍锁定的互斥关系见 [[定时换班]]·MAA 执行）。

## 请求限流与注册登录

**问：生成排班时一直提示「请求排队/请求过于频繁」或直接失败报错，应该怎么办？注册登录类问题怎么解决？**

请求排队、请求过于频繁与失败报错的处理顺序：

1. 停止连续点击生成。
2. 等待当前请求结束。
3. 等待限流恢复。
4. 刷新页面后只提交一次。
5. 检查网络和登录状态。
6. 仍失败则重新登录后再试。

注册登录问题：

1. 注册后需要填写邮箱验证码，验证码一般为 6 位。
2. 验证码过期时需要重新发送。
3. 收不到邮件时，检查垃圾邮件、广告邮件和邮箱拦截。
4. 使用网站支持的邮箱账号登录。
