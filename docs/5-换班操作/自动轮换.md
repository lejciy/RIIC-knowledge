# 自动轮换

## 一句话结论

自动轮换是游戏内置的换班方式：设施工作队列中出现注意力涣散（俗称红脸）干员时，游戏自动从该设施的预设替补队列中挑一队顶上，再配合干员休整一键把换下的人填进宿舍。没有固定时刻表，上线时间不固定的玩家用它最省心；前提是每个设施提前配好替补队列。

## 换班原理

自动轮换的触发、选队、替换全部由游戏裁决，玩家只做两件事：预先配队、上线按键。

- **触发信号**：设施当前工作队列中存在注意力涣散干员，且该设施存在可用替补队列——没有涣散干员则不发生换班，没有可用替补则无人可换，两者缺一不可。全局批量应用（代办事项/进驻总览→队列轮换）与单设施切换（基建总览-设施详情右侧切换队列）采用同一判定逻辑。
- **替换范围**：以设施为单位整队替换，换上的是当前**可用**的队列——即队列干员均未在其他设施进驻；干员正被其他设施使用的队列无法应召。
- **选队判定**：所有干员均未处于训练室训练位＞总心情比例最高＞队列序号靠前（细则见 [[队列轮换]]·切换队列）。
- **班次概念**：无固定班次与时刻表，红脸才换、不红不换——换班节奏由各设施的心情消耗速率自然决定。
- **宿舍配套**：换下的干员经干员休整一键进驻宿舍（按心情由低至高选人、按氛围与楼层选位，细则见 [[队列轮换]]·干员休整）。

## 操作过程

1. **前置配置**：为每个工作区设施（控制中枢、生产设施、会客室、办公室）编辑并保存预设队列（步骤见 [[队列轮换]]·编辑预设队列）。建议每个设施配两组完全不同的组合：一组主力、一组替补，且各设施的主力与替补互不重复——替补队列里的干员一旦正被其他设施使用，该队列就不可应召，重复配置等于没有替补。
2. **日常执行**：上线后打开代办事项或进驻总览→「队列轮换」一键批量切换，再执行「干员休整」把换下的干员填进宿舍；也可在单个设施的详情页手动切换队列，判定逻辑与批量应用相同。
3. **范围例外**：训练室与加工站无法配置预设队列，在其中工作的干员既不适用队列轮换，心情涣散时也无法通过一键休整换下，需要手动管理（见 [[基建总览]]·训练室/加工站队列豁免）。
4. **宿舍常驻位**：宿管干员或挂件位若需要常驻，先在宿舍锁定编辑，再执行休整与轮换，锁定位不受一键休整影响（见 [[队列轮换]]·锁定编辑）。

## 特有规则

- **跨设施体系会错班**：不同设施、等级与技能配置之间存在心情消耗速率差异，同一体系的中枢端与生产端不会同时涣散，而自动轮换按设施独立触发——体系两端错班后，中枢光环空转、生产端缺加成，产生效率损失。强绑定的跨设施体系（[[感知信息组]]、[[红松林骑士组]]、[[自动化组]]（中枢森蚺）等）不建议在自动轮换下使用；组合选择优先单站生效组合，或跨设施数不超过 2 的组合。
- **同产物多设施同步涣散**：从初始状态同步上班时，同类型同产物的多座生产设施（如两座赤金站、两座经验站）心情消耗完全同步，无额外减免时几乎同时涣散——因此每座设施都要配置自己的主力＋替补；只给其中一座配替补，涣散潮到来时其余设施无队可换。

## 常见误区

- **以为自动轮换会按时自动换班**——触发条件是队列中出现注意力涣散干员，没有涣散就不发生任何换班动作；它等价于「红脸了才换」，不存在时刻表。
- **以为一队替补可以服务多座同类设施**——同产物设施同步涣散，替补队列一旦被最先涣散的设施占走，其余设施在那一刻就无队可换；替补按设施独立配置、互不重复。
- **以为训练室、加工站的红脸干员能被一键处理**——两类设施没有预设队列功能，其中的干员即使涣散，队列轮换与一键休整都覆盖不到。
