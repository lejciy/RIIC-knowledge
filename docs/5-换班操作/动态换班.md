# 动态换班

## 一句话结论

动态换班（mower 功能名为「按心情动态换班」）是以干员心情状态为信号、随时换人随时休息的换班方式：心情掉到设定阈值就换下进宿舍，休息好了立刻回岗，在工休比允许的范围内把在岗时间吃满。轮休规则与错班轮换同源，固定班表被心情状态取代，决策与执行全部交给外部工具 7×24 小时代理。仅适合搭配 [mower](https://github.com/ArkMowers/arknights-mower)（[说明文档](https://arkmowers.github.io/arknights-mower/)）使用，人类手操作无法覆盖全天候的换班与跑单时机；适合有常开设备挂机、追求极限产出的玩家。

## 换班原理

动态换班的轮休底层与 [[错班轮换]] 相同：工作消耗与宿舍恢复构成循环，工休比决定可持续的在岗上限。差异全在执行侧——定时换班按人类操作习惯把循环切成固定班次、到点整批轮换；动态换班面向机器操作，随时可进宿舍与设施，循环按每个人的心情状态独立驱动。[[心情与宿舍]]·班次结构的推导约束指出：每宿舍一群回＋一单回、各组错峰入住可最大化工作占比，但工作与休息时间完全离散，仅全自动换班可执行——动态换班即把这个理论上限兑现的形态。

- **触发信号**：心情阈值。在岗干员心情降至阈值即换下、进宿舍休息，休息达标立即回岗；换班发生在注意力涣散（红脸、技能失效）之前，主力几乎不产出涣散损失。自动轮换的触发信号是涣散本身，涣散已意味着加成失效——两者信号时机不同，动态换班更早。
- **换的范围**：以「组」为粒度。绑定为同组的干员（一个单站组合，或中枢＋生产端的跨设施体系）同时上下班，一次只换下需要休息的那一组；基建内其余设施不动。整班轮换一次换下基建半数设施的编制，宿舍容量与暖机损失都大（见 [[定时换班]]·两班轮流），按组换班把这两项代价降到最小。
- **替补来源**：替换组（替班）按需顶岗。哪个主力组到阈值，替班就顶哪个组，替班与主力之间无固定配对——一名替补干员可以服务多名主力的轮流休息（mower 排班规则）。这是 N＋1 轮换的深化：三班倒里一个替补组顶两个主力组，替补的工作占比尚有余裕；动态换班下替班按实际休息需求上岗，余裕可以兑现为更多主力组共享同一个替班，省下的都是低效率递补组的在岗时间。
- **班次概念**：无固定班表，换班节奏由各组心情消耗速率自然形成。工休比仍是硬约束：组内消耗最快的干员决定整组节奏（跨设施组合的瓶颈判例见 [[心情与宿舍]]·锚点与推论），替班承担的总休息时间也受自身工作占比约束（见特有规则）。

## 操作过程

1. **规划布局与组合**：组合选择与体系优先级照常规划（见 [[组合总览]]），各组合的轮休可行性按工休比核算（见 [[错班轮换]]·轮休的原理）。高效组合进主班（主力位），低效率递补组合进替班（替换位）。
2. **编辑主表**：在 mower 排班编辑中为每个设施填主班与替班两套人选；必须同时上下班的干员（跨设施体系成员、同组绑定的组合成员）编为同组。跑单干员（龙舌兰、但书）只能放在替换组第一位并默认开启跑单，同一替换组内两者不可混放（校验规则见 mower 文档）。
3. **配置宿舍**：每间宿舍安排一名单体回复＋一名群体回复宿管、置于宿舍最左位，并保留空位供轮换干员入住（mower 硬性要求；单回复制锁定首位入住者的机制见 [[心情与宿舍]]·单体回复的锁定规则）。回复能力分档约定（下层宿舍回复能力不超过上层）等宿舍排表细则以 mower 文档为准。
4. **逐人设置**：在设置区按干员填特殊开关——暖机主力设「回满」＋「用尽」；不允许进宿舍的干员填「黑名单」或「0 心情」；菲亚梅塔指定轮换对象；低优先级干员与休息优先级按需配置（口径见特有规则）。
5. **按需编写副表**：副表＝条件＋任务——条件可读取干员工作状态、位置、心情与线索交流结束时间，用 and/or/比较运算符组合；任务为换班动作，生效时覆盖主表的差异位置。触发时机选在换班或收取任务的节点上（结构见 mower 文档·排班教学）。
6. **常驻运行**：设备挂机运行 mower，换班、跑单、收取自动执行；按运行日志与基建报表核对执行情况。

## 特有规则

- **宿舍满配回复**：每间宿舍同时配备单体＋群体宿管，把该宿舍的恢复能力拉到档位上限（满级宿舍＋宿管后单人恢复约 4~6/h，见 [[心情与宿舍]]·恢复公式）。回复速度直接决定工休比上限，是动态换班压缩休息时间的基础投入。
- **替班的工作占比上限**：替班可服务的主力数量有上界——需替换的主力的休息时间占比之和，不得超过替班自身的最高工作时间占比（mower 教程按替班干员睡低优先级宿舍位核算，约 77%）。高消耗组（如歌蕾蒂娅所在的深海猎人组）与常驻体系要单独核算，超出即需增加替班人手。
- **跑单**：贸易站每一笔订单刷新的瞬间插入但书／龙舌兰，吃满特殊订单加成后立即撤出、换回纯高效率组——Lv.1/Lv.2 站插入但书，Lv.3 站插入龙舌兰＋但书（技能触发原理见 [[但书]]·特殊用法）。订单刷新时间离散，人类手操只能覆盖上线时段；7×24 运行的工具才能让每一笔订单都吃到加成。
- **宿舍黑名单／0 心情**：两者都表示不安排进宿舍休息，「0 心情」作用于主力干员、「黑名单」作用于替换组与表外干员。典型用例是自动化组中枢森蚺分支的 Lancet-2——她必须全程保持 0 心情红脸，「我寻思能行」与「晨曦」才同时在线（见 [[自动化组]]）；动态换班的自动休整会把红脸干员填进宿舍，黑名单显式排除后该玩法才可持续。
- **回满与用尽**：仅适用于主班干员的一对开关。「用尽」让干员坚持到心情真实耗尽前才下班（mower 计算真实用尽时间、提前 8~10 分钟安排休息），「回满」让干员休息至满心情再上岗——两端拉满即最大化单次连续在岗时长。适合有暖机的干员：阿罗玛「例行清扫」（进驻后生产力每小时 +2%、封顶 +20%）、伊内丝「聚影」（线索速度 +20%、每小时 +2%、封顶 +30%）等，技能在换位时暖机重置（见 [[基建总览]]·暖机重置），长单班才能吃满爬升后的高效率时段。
- **菲亚梅塔 3＋1**：常规换班下菲亚梅塔的输送容量恒为 2/h，Lv.3 满员三人消耗 1.95 ≤ 2.0，可持续轮换三人（容量判据见 [[菲亚梅塔]]）。动态换班可在此之上指定第四个轮换对象：三人常规轮换留下的回复余量（2 − 1.95 ＝ 0.05/h）会随使用周期积累，菲亚梅塔一经回满就把满心情输送给第四人——余量足以周期性多用一次，容量之外的对象按此低频接入，与持续轮换区分。

## 常见误区

- **把动态换班等同于游戏内置的自动轮换**——触发信号（心情阈值 vs 涣散）、换班粒度（组 vs 设施整队）、执行者（外部工具 vs 游戏内置判定）三者均不同；阈值触发在涣散前完成换人，主力不存在红脸空转期。
- **换班阈值设得越早越保险**——阈值提前只压缩在岗时间与暖机收益；阈值应按各组工休比核算，并为工具的心情读取周期留出提前量。
- **一个替班可以无限多带主力**——替班承担的休息时间占比之和受自身最高工作时间占比约束（mower 教程口径约 77%），高消耗主力还要按其净耗单独复核。
- **跑单需要给但书/龙舌兰保留常驻编制**——跑单只吃订单刷新瞬间的触发，工具在刷新前后自动插入与撤出，主班效率位照常满配高效率干员。
- **红脸挂件可以交给自动休整处理**——Lancet-2 一类依赖 0 心情状态的触发件被休整填进宿舍即回心情、体系加成中断；必须写入黑名单或 0 心情名单。
- **回满与用尽可以全队铺开**——该开关仅对主班干员生效（mower 校验规则），替换组干员靠低优先级宿舍位与宿管覆盖即可。
